# PDF Tools — Internationalization (i18n)

## 1. Locales (20)

| Code | Language | RTL |
|------|----------|-----|
| `en` | English (default) | no |
| `hi` | Hindi | no |
| `bn` | Bengali | no |
| `as` | Assamese | no |
| `es` | Spanish | no |
| `pt` | Portuguese | no |
| `fr` | French | no |
| `ar` | Arabic | **yes** |
| `ur` | Urdu | **yes** |
| `zh` | Chinese (Simplified) | no |
| `ja` | Japanese | no |
| `ko` | Korean | no |
| `ru` | Russian | no |
| `id` | Indonesian | no |
| `de` | German | no |
| `tr` | Turkish | no |
| `it` | Italian | no |
| `vi` | Vietnamese | no |
| `th` | Thai | no |
| `ta` | Tamil | no |

Same list as ImgLove (proven). RTL: `ar`, `ur` → `dir="rtl"` on `<html>`, logical CSS properties everywhere (`ms-`/`me-`, `ps-`/`pe-`, `start`/`end` — never physical left/right in components).

## 2. URL scheme — English default at root

Astro i18n config: `defaultLocale: 'en'`, `prefixDefaultLocale: false`.

| Content | English (default) | Other locale (example: Hindi) |
|---------|-------------------|-------------------------------|
| Home | `/` | `/hi/` |
| Tool | `/merge-pdf/` | `/hi/merge-pdf/` |
| 404 | `/404/` | `/hi/404/` |

- No `/en/` URLs exist. The locale switcher on `/merge-pdf/` links to `/hi/merge-pdf/` (same tool, keeps context).
- `tools.ts` registry holds the English slug; localized slugs are NOT used (one canonical slug per tool across locales — simpler hreflang, better SEO consolidation).

## 3. Dictionary structure (`src/i18n/locales/<code>.ts`)

Mirroring ImgLove's `dicts.ts` pattern — one flat-ish namespaced object per locale, fully typed against the English dict (TypeScript enforces every key exists in every locale; build fails on missing keys):

```ts
// en.ts (source of truth)
export default {
  nav: { merge: "Merge PDF", split: "Split PDF", /* ... */ },
  hero: { title: "Every tool you need...", sub: "..." },
  categories: { all: "All", organize: "Organize", /* ... */ },
  tools: {
    merge: { name: "Merge PDF", desc: "Combine PDFs...", },
    // ... one entry per tool, keyed by registry key
  },
  workspace: {
    selectFiles: "Select PDF files",
    orDropHere: "or drop PDFs here",
    addMore: "Add more files",
    // ... all shared workspace strings
  },
  errors: { tooBig: "File exceeds the {limit} limit.", /* ... */ },
  footer: { /* columns */ },
  faq: { /* per-tool Q&A */ },
}
```

## 4. Translation workflow

1. Write/extend **English first** (`en.ts`) — it's the type source.
2. Translate the new keys into the other 19 dicts. Machine-assisted draft + human review for `hi`, `ar`, `ur` (user's own languages); others machine-drafted, reviewed opportunistically.
3. `astro build` type-checks dict completeness — missing keys fail the build loudly.

## 5. SEO + locale

- Every page emits `hreflang` for all 20 locales + `x-default` pointing at the English root URL.
- `<html lang="<code>">` per page; OG locale tags (`og:locale`, `og:locale:alternate`).
- Sitemap (`@astrojs/sitemap` i18n mode) lists every locale variant.

## 6. Fonts per script

Inter covers Latin/Cyrillic/Greek/Vietnamese/Thai. For `ar`/`ur`/`hi`/`bn`/`as`/`ta`/`zh`/`ja`/`ko`, add system-font fallbacks in the font stack (`"Inter", system-ui, "Noto Sans", sans-serif`) — v1 does not bundle CJK/Indic webfonts (too heavy); the stack degrades gracefully.
